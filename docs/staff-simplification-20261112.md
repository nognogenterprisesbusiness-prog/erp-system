# Staff simplification and complete reads

Implemented server-filtered attendance before pagination, complete payroll aggregates, paginated payroll display, streamed formula-safe CSV exports, full worker-card reads, compact stock cards, stable guarded edit dialogs, lazy employee-form reference loading, and daily-task-first navigation. Warehouse uses Inventory instead of an empty project dashboard. Mobile notifications use a preview, explicit read-state action and PHT time; report history is clearly distinguished from creating a daily report.

Required employee details remain visible. Optional middle name/email/account fields are grouped, not deleted from stored records. Stock reservation/minimum rules and operational receipt/approval steps remain authoritative. Complete payroll totals now come from SQL rather than the displayed page. The department subtotal block was removed from the detail summary; department remains on employee rows and in complete CSV exports.

Verification: 176 web tests (including streamed 1,500-row CSV and formula escaping), 31 mobile tests, web/mobile typechecks and lint, Android/iOS export. The isolated PostgreSQL scale suite creates over 1,100 employees, checks full totals and denied roles, and finds an attendance worker beyond page one. Browser checks against user-confirmed staging migration covered global-search empty result, full-scope payroll screen, compact inventory and lazy employee form with required contact and optional details. No hosted records were created or changed during browser checks. Mobile physical-device, camera/QR, release-AAB and real-network performance benchmarking remain separate verification tasks; native bundle export is not a Play Store release.

The new migration adds two Admin/Finance read functions. It does not delete rows/tables, loosen RLS, alter posting rules or change mobile write protocols. Applied migrations were retained; deleting the historical chain is unsafe without a separately verified baseline and deployment-history reconciliation. Cleanup removes replaced attendance filtering, misleading inventory charts, duplicate card targets, unused imports and eager list-page form-reference queries. No measured latency or claim of complete codebase dead-code elimination is implied.
