# Restored mobile material purchases

Home selects the project/site. Buy at hardware store → New purchase collects an active hardware store, existing catalog materials, quantities, unit prices and receipt photo. The total is calculated. There are no extra project, date, receipt-number, payment-source or notes inputs. The existing company-cash default remains. Diesel stays a separate vehicle-linked receipt expense.

Submission creates a pending inventory purchase without stock or material cost. Admin or Finance verifies and approves receipts up to PHP 50,000; above PHP 50,000 only Admin can approve. Approval posts each material to the selected site once with its cost batch and supplier provenance. Actual site consumption deducts stock and records project cost once. Reimbursement cannot duplicate stock. Existing receipt-only expense records and older mobile commands remain compatible; historical expenses are not silently converted to stock.

The new submit_mobile_site_purchase wrapper reuses the existing audited submit/approval commands. It generates the Philippine submission date and a MOB system reference, marks that reference as generated, and retains it during retries after midnight. The generated reference is explicitly labelled System reference on the web detail. The actual supplier remains required rather than guessed. Purchase history includes material names, quantities and units.

Deploy web main and apply supabase/migrations/20261013190000_mobile_itemized_site_purchases.sql after preceding migrations before distributing this mobile build. The migration adds one metadata column and one narrow RPC; it does not rewrite stock, expenses, costs or past receipts.
